# dataset

추천 스크립트(`job_recommender.py`)가 사용하는 표본 데이터.

## 파일

| 파일 | 내용 | 행 |
|---|---|---|
| `JOB_DATA.csv` | 장애인 채용공고 표본 (38개 항목) | 854 |
| `USER_DATA.csv` | 구직자 희망조건 표본 (12개 항목) | 5 |

## 개인정보 처리

`JOB_DATA.csv` 는 공개 채용공고에서 수집한 자료이며, 채용 담당자의 성명·연락처·이메일과
기업 대표자 성명이 포함되어 있었다. **본 저장소의 파일은 이 항목들을 마스킹한 것이다.**

| 항목 | 처리 |
|---|---|
| 담당자명 · 기업정보.대표자 | `김현욱` → `김*욱` (성과 끝 글자만 유지) |
| 연락처 | `010-2776-9672` → `010-****-9672` (국번·끝 4자리 유지) |
| 이메일 | `gaeon.kim@example.com` → `ga***@example.com` (도메인 유지) |
| 자유텍스트(접수방법 등)에 포함된 전화·이메일 | 위와 동일 규칙으로 치환 |

- 마스킹은 `../mask_pii.py` 로 수행한다. `python mask_pii.py` 는 검사만, `--write` 가 실제 교체.
- 담당자명 자리에는 기관명(`부산광역시 사하구청`)도 섞여 있어, **개인명 형태로 판별된 값만** 마스킹한다.
  판별되지 않은 값은 실행 리포트의 `[미마스킹]` 목록으로 출력되므로 사람이 확인한다.
- 마스킹 대상 항목은 추천 로직이 사용하지 않는다(특징 컬럼은 `직무`·`담당업무`).
  마스킹 전후 추천 결과가 동일함을 확인했다.

> 실제 담당자 연락처가 필요한 기능(예: 지원처 안내)은 이 표본이 아니라
> 접근통제가 적용된 DB의 원본을 사용한다. 원본은 저장소에 두지 않는다.
